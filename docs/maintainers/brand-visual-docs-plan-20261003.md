# 官网与文档第二轮重构规划

## 要解决的问题

第一版在导航中展示了图标，但首屏没有建立产品身份；功能、宣传语和补充说明同级出现，阅读顺序不明确。翻译动画只播放一次，停留后看不出变化。文档入口主要是文字卡片，部分指南把兼容细节与核心步骤混在一起。

## 架构决定

保留 Vue、TypeScript 和 VitePress 的静态生成、搜索、双语路由及 GitHub Pages 部署。首页使用独立的自定义页面和设计系统，文档采用定制的操作演示组件。布局不受默认首页模板约束。本轮没有需要更换构建框架才能实现的功能，因此先通过自定义布局实现目标，减少迁移造成的链接、搜索和维护负担。

## 首页阅读顺序

1. **认识 FluentRead**：首屏突出正式 A/中循环箭头图标与名称；保留既有品牌文案，用一句具体描述说明网页双语翻译。一个主要安装按钮，一个文档入口。
2. **直接看见变化**：首屏自动展示“原文 → 翻译出现 → 双语对照”，可暂停、重播、手动切换。动作持续可见，并显示当前演示步骤。
3. **从译文到理解**：只用一个句子展示词性与句法。保持原句、彩色角色标注和短解释；点击片段获得具体含义，避免重复的学习宣传区。
4. **按内容选择入口**：图片、文档、视频、输入与写作使用四张视觉示例；每张只讲一个场景，附对应指南。图解由 HTML/CSS 渲染，真实界面截图用于操作定位。
5. **开始使用**：安装、选语言、翻译三步。免费/服务/隐私等补充信息与常见问题默认折叠；页脚保留官方资源与支持入口。

首页删除重复的功能介绍、服务名称墙和大段兼容说明。不能只做入场渐显，动画必须解释一次真实操作和结果。

## 文档模板

每个任务页按“能做什么 → 可操作的图解 → 3–4 个关键步骤 → 结果与下一步”组织。设置位置和按钮名称明确，示例与真实扩展功能区分。第一次使用与主要能力先展示必要内容；进阶设置、兼容边界、完整格式、迁移和排查细节放在默认关闭的折叠块中。

- 文档首页突出快速开始和常用任务；其他主题可展开查找。
- 左侧目录保留快速开始，其余专题默认折叠，并让当前专题可见。
- 图解复用一个视觉组件体系，覆盖网页、划词、图片、圈选、文件、字幕、输入、写作、服务与外观等任务。
- 高清真实截图保留可点击原图，用于扩展菜单、划词与设置定位。
- 隐私与重要限制在相关操作旁明确说明；完整政策保留可检索的章节。
- 中英文布局与能力说明一致，旧链接和章节锚点继续可用。跳到折叠内容的锚点时自动展开对应块。

## 动画与无障碍

动画只在演示可见且页面处于前台时运行，离开视口或页面隐藏时暂停；卸载清理计时器与观察器。提供明确的暂停和重播控制，手动操作后停止自动切换。遵循减少动态效果偏好，静态显示完整结果。使用键盘可操作的原生按钮、分组和折叠，避免自动演示频繁播报。

## 视觉与资源

从正式品牌图标提取玫红色，使用温暖白底、深色正文、较少边框与足够留白。首屏图标必须在桌面与手机可见。图片明确尺寸、按需加载，优先无损 WebP。演示文字真实可选、可缩放；不用整张截图承载关键说明。

## 验收

- 首屏一眼可找到图标、产品名称、核心价值、安装入口和正在发生的翻译。
- 首页有明确的内容层级，主要内容没有重复宣传或长篇说明。
- 主要指南有具体操作图解，进阶内容默认折叠；直接访问旧锚点可以看见对应内容。
- 桌面、平板和 320/390px 手机无横向溢出；深色和减少动态效果可用。
- 网站类型检查、静态构建、内部链接/锚点/图片检查通过。
- 浏览器核验自动播放、暂停、重播、手动操作、折叠、搜索、双语及相关路由；保存首屏与文档截图。

## 交付顺序

本规划先写入独立工作树，再实现共享演示与首页，随后改文档和折叠行为，最后检查真实浏览器效果并交付预览。完成验证后再按已有发布授权处理 GitHub 交付。
