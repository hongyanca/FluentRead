## 产品组织

网站规则移到“系统与数据”，保留原有 section ID、设置搜索和跨页入口。普通设置沿用主分支的同页布局；网站规则保留任务视图，避免把日常偏好、结构编辑和问题诊断混在一张长表单中。

| 视图 | 用户需要回答的问题 | 调整方式 |
| --- | --- | --- |
| 网站偏好 | 这个网站要不要自动翻译、禁用扩展或隐藏悬浮球？ | 同站一行、三个独立偏好；可粘贴网址、搜索、移除及撤销 |
| 正文适配 | 哪些区域翻译，哪些保留原文？ | 内置 / 自定义 / 已停用筛选、可读详情、可视化表单，按需展开高级 JSON |
| 生效预览 | 为什么这个网址没有按预期工作？ | 解释已保存配置的优先级、命中规则与识别范围，并跳转到规则详情 |

网站偏好仍使用已有三个配置数组，不创建第二份数据源。禁用扩展优先于自动翻译，但不删除其他偏好；暂停插件也不会清空名单。域名仍按现有 Public Suffix List 逻辑归并，路径、参数和端口不会变成网站偏好。

## 修改必须可理解、可撤回

- 日常偏好即时提交，但只有后台确认后才显示已保存。立即关闭设置页的交接沿用现有配置端口。
- 正文规则先编辑、暂存，再明确保存和应用。目录允许检查草稿；生效预览只读取已保存配置，二者明确标注。
- 表单与 JSON 共用一份草稿。CSS 按行分隔，不拆逗号；模板先展开，未展示的高级字段完整保留。
- 内置规则可建立同 ID 自定义覆盖；移除覆盖并保存后恢复内置版本，停用状态仍按 ID 保留。
- 导入默认合并，不清空其他规则；同 ID 整条替换，冲突模板拒绝合并。完整替换是显式选项，保存前可撤销。
- 外部页面更新不会吞掉本地草稿，旧草稿不能静默覆盖新配置；可导出草稿、恢复最新配置、重新合并。
- 未保存草稿、已改表单及待确认保存会注册浏览器离页提醒；干净状态和组件销毁时移除监听。提醒不是自动保存，确认离开仍可能丢失草稿。

内部识别仍复用既有规则编译器和运行时约定，没有重新定义网页翻译策略。全部节点范围只应用显式声明 `allScopes` 的规则；预览会保留网址命中信息，但明确标出不适用的规则。

## 第二轮设计复核

普通用户主要使用网站偏好和开箱即用的内置规则，无需先学习 JSON。高级用户可以渐进地增加路径、多个正文区域和保护选择器，也可以继续使用完整规则包。结构适配仍需要理解网站 DOM；可视化表单不应暗示 CSS 可以自动猜对。

重心是“能看懂为什么、能调整、能恢复”，而不只是让规则库看起来更整齐。复核中修正了乐观配置回显被误报为保存完成、全部节点预览范围不一致、按钮悬停对比度以及全局自动翻译下的空状态文案，并补上未保存离页保护。
