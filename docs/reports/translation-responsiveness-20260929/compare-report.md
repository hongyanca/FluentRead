# 大型 GitHub 对比页性能修复

日期：2026-09-29。这是[第一阶段](./report.md)后的继续优化，基线为本地提交 `0d17e95f`。没有发布扩展，也没有执行全量回归。

## 根因与实现

- **代码行进入正文扫描。** GitHub compare 的源代码放在 `td.blob-code`，不是普通 `pre/code`。网站规则现在在代码行边界裁剪发现、文本提取和变更观察，同时保留同一 diff 表格中的审查评论。规则仅针对 `github.com`，不排除整张 diff 表格。
- **外部译文边界查询随 DOM 写入反复搜索大子树。** 祖先检查使用原生 `matches(':has(> .immersive-translate-target-wrapper)')`；旧 WebView 不支持时每个文档只探测失败一次，然后回退类名集合与父级核对。仅缓存选择器能力，不缓存 DOM 结论，因此节点插入、删除、移位、改类和 Shadow DOM 仍实时生效。原生选择器的兼容范围可见 [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/:has)。
- **读取尺寸触发页面布局。** 识别无障碍裁剪文本时先检查定位、overflow 和裁剪，再读取确实需要的宽高，普通定位容器不再进入几何读取。
- **同一结果多次收集文本槽、交错读写 DOM。** 替换式渲染复用同范围的完整槽快照；先验证宿主当前内容，再将 loading 移除与译文写入合并在同一个视口补偿中。保存恢复快照时先移除 loading，避免把加载图标存回原文。
- **快速请求产生短命 loading 节点。** 全文请求等待 180ms 后才为仍有效的请求显示 loading；快速响应和缓存命中不再插入又删除图标。悬浮翻译仍即时反馈。取消、结束、节点脱离、会话替换和请求完成都会阻止迟到图标出现。

第一阶段的 8ms 派发时间片、提交前让出主线程、所有权释放优化及中文名称识别保留。此次没有引入新依赖。

## 固定页面的前后对照

用户提供的 `main` 会变化，因此两版都测试[固定比较地址](https://github.com/openai/codex/compare/rust-v0.160.0-alpha.3...d7f7fa410698fbbb75548cde553a4fbf43fc268e)。同为 64,645 个宿主 DOM 元素、665,663 个文本字符；启用扩展后多一个样式节点。

隔离 Edge 加载 Chrome 生产扩展，CDP 4 倍 CPU 降速，全文范围为 all，并发 10，本地固定微软协议响应 5ms。每版独立临时 profile，等待页面加载后 8 秒再采样；不同时运行构建。翻译和重译阶段各观察约 15 秒，其他阶段约 3 秒。计时包含浏览器实际调度等待，原生 CDP 点击固定宿主按钮，不依赖重复全页定位器扫描。

| 指标 | 基线 | 修复后 |
| --- | ---: | ---: |
| 翻译窗口内显示的双语块 | 12 | 25 |
| 翻译窗口内供应商处理条目（含控件） | 57 | 91 |
| 翻译窗口样式重计算耗时 | 1,813ms | 75ms |
| 翻译窗口心跳 P95 / 最大间隔 | 837 / 889ms | 278 / 394ms |
| 翻译窗口累计阻塞时间 | 3,460ms | 3,525ms |
| 翻译窗口最长单次任务 | 175ms | 289ms |
| 滚动期间累计阻塞时间 | 975ms | 156ms |
| 首次恢复累计阻塞时间 | 424ms | 212ms |
| 重译窗口样式重计算耗时 | 1,325ms | 62ms |
| 重译窗口累计阻塞时间 | 4,155ms | 2,903ms |
| 重译窗口心跳 P95 / 最大间隔 | 537 / 711ms | 355 / 1,101ms |
| 重译窗口最长单次任务 | 232ms | 253ms |
| 再次恢复累计阻塞时间 | 328ms | 215ms |

累计阻塞时间为每个长任务超出 50ms 的部分之和。固定时间窗口内完成的工作量不同，不能据此声称完整页面快了多少倍，也不能用每段平均值掩盖卡顿。样式重计算约降低 96%，滚动阻塞约降低 84%；翻译总阻塞未下降，最长点击完成时间从 222ms 变为 288ms。重译最大心跳间隔也没有改善，不将心跳延迟解释为同等时长的单个 JavaScript 任务。

CPU profile 仍显示视口补偿的 `elementFromPoint` 命中测试和 GitHub 自身观察器的查询占用时间。本次保留滚动位置保护，没有缓存可能过期的宿主布局，也没有宣称所有长任务消失。单轮采样受主机负载和宿主脚本影响，不是统计学性能保证。

所有发出的宿主探针点击均被处理；各次恢复无残留译文，缓存重译没有新增供应商请求。最终产物每阶段检查 4,889 个仍连接的代码单元，原文变化数为 0。测试模拟的是宿主独立按钮，不等价于检查了 GitHub 每个原生控件；行内审查评论由 DOM 回归用例覆盖。

原始测量：[基线](./compare-before.json)、[修复后](./compare-after.json)。仓库副本仅保留性能及必要环境字段，省略本地绝对路径、桌面位置、前台应用、进程信息和页面正文快照。启动方式为 `macos-background-cdp` / `launchservices-no-foreground`，第二屏正常可见窗口，`browserFrontmost=false`。CPU profile 和完整 HTML 仅作为本地诊断产物。

| 空闲页面及功能开关 | 可选功能按配置挂载并清理；生命周期、悬浮和消息入口测试通过。对比页启用扩展后的空闲采样无长任务。 |

| 请求队列及页面上下文 | 有并发限制、取消、队列推进与上下文上限；相关测试通过。没有新增逐段远程语言识别。 |

- `dom.ts`、`liveTextRender.ts`、`loadingIndicator.ts` 的 statements / branches / functions / lines 均为 100%；该严格覆盖率运行含 9 个文件、465 项。没有将整个 runtime 的覆盖率算成 100%。
- TypeScript/Vue 类型检查、测试审计、Chrome/Firefox 生产构建、manifest 校验、userscript 构建与 verifier 通过。依赖来自已有本机安装及临时依赖链接，未修改锁文件，不是全新安装验证。
- 最终 Chrome 生产包完成 1,500 个英文段落的翻译 → 滚动 → 恢复 → 重译 → 恢复，4 倍 CPU 降速。首译 41.22 秒，重译 46.53 秒，两者长任务均为 0；首译、滚动、重译分别完成 94、12、122 次宿主按钮点击。恢复仍有一个 249ms 任务，未宣称恢复无阻塞。中文段落始终保持原样，供应商未收到该中文段落。见[最终长文数据](./final-stress.json)。
- 最终包再次验证真实中文 README 和 Issues 页面，两个页面都完成翻译、恢复和重译；截图所示中文段落的 `innerHTML` 不变且零供应商请求，英文内容仍生成译文，脚本异常为 0。见[最终 GitHub 数据](./final-github.json)。

## 复现

```bash
pnpm build
node scripts/testing/run-resource-safe.mjs -- \
  node scripts/testing/run-translation-responsiveness.cjs \
  --compare --repeat --check-code --cpu-rate 4 \
  --page-url https://github.com/openai/codex/compare/rust-v0.160.0-alpha.3...d7f7fa410698fbbb75548cde553a4fbf43fc268e \
  --artifacts-dir /private/tmp/fluentread-compare-performance
```

基线加 `--extension-dir` 指向 `0d17e95f` 的独立生产构建，并省略针对新代码保护规则的 `--check-code`。脚本支持 `--measure-ms` 调整观察窗口，`--boundary-benchmark` 仅供选择器诊断。时间阈值不作为 CI 硬断言。
