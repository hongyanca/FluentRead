# X AI 字幕识别与性能验证（2026-10-06）

本次修复保留当前浏览器内的 Whisper Tiny/Base 多语言模型，处理 X 播放器媒体身份补全时丢失字幕、首窗语言误判固定全片、中文解码截断、长串重复输出以及 Home 旧清单读取失败。新增可重复的真实模型基准，后续模型和参数变化继续对照原始文字、耗时和资源数据。

## 已实现的行为

- 同一媒体的 poster 补全、控件重建、鼠标移出/移回、video 节点替换、暂时隐藏保留时间轴；不同媒体清理旧字幕。媒体身份补全仅保存一次新缓存别名，普通重挂载不重复读写缓存或启动 ASR。
- 自动语言检测需要两个至少 3 秒、置信度至少 0.8 的连续音频窗一致才固定语言。低置信度窗口不会污染整片语言缓存；显式源语言跳过检测。
- 中文、日语、韩语增加有上限的 token 预算，英文预算保持原值。限制重复 n-gram，检测长串重复后只重试一次；仍异常则报错，也拒绝恢复含重复乱码的旧缓存。
- Home 用当前唯一视频的相邻媒体缩略图补充身份；新清单优先，失败后最多尝试三个同媒体清单，共享 30 秒读取期限。仍不猜测多个不明媒体组。

## 真实 Whisper 基准

环境：MacBookPro18,1、10 逻辑 CPU、32 GiB RAM；临时后台 Edge，Tingting 普通话合成语音，16 kHz 单声道 PCM。对照两份生产构建，模型在本机实际运行。基线识别源码来自 `5e8a22337c18944f344f9ffb3a54559294d65892`；候选识别源码随后 rebase 到 `a958891b3246da0335c0b4c3234755d286e8bd73`，此 rebase 没有改变识别 Worker 或生成参数。

[原始 q4 对照报告](./recognition-q4.json)记录三段语音、显式中文与自动检测，以及 Tiny/Base 的全部结果。CER 忽略标点，但仍把简繁字形差异计为错误，不能将它直接等同于中文语义错误率。

| 样本（显式中文） | Tiny 原版 → 修改版 CER | Base 原版 → 修改版 CER | 实际观察 |
| --- | --- | --- | --- |
| 3.48 秒古装对白短句 | 20.0% → 20.0% | 33.3% → 33.3% | 两个模型均有同音字错误；Base 在此样本更差 |
| 5.86 秒普通说明句 | 46.2% → 46.2% | 3.8% → 3.8% | Tiny 包含简繁差异和“10别”；Base 错一个字 |
| 9.22 秒较快长句 | 44.2% → 36.5% | 28.8% → 28.8% | Tiny 句尾从“输出大”恢复为“输出大量重複文字”；Base 原本完整 |

长句 Tiny 转写耗时 1.484 → 1.651 秒，Base 2.210 → 2.234 秒。普通说明句约 Tiny 1.05 秒、Base 1.55 秒。首次推理包含模型初始化和 GPU 冷启动；第二构建复用了下载缓存，不能把首次下载/推理差异当作代码提速。自动检测的第二次确认增加一次语言检测成本，确认后复用；显式中文没有此成本。

该测量没有证明内存显著下降。q4 对照中的隔离浏览器累计 RSS 峰值约 2.5–2.8 GiB，包含浏览器、GPU、工具进程和共享页重复计数，不等于扩展独占内存或 GPU 显存。当前降低无谓消耗的实际改动是阻止悬浮/重挂载导致的重复识别和缓存工作，以及有界的异常重试。

### q8 量化实验

[原始 q8 实验报告](./recognition-q8-experiment.json)中的 `baseline` 是修改后的 q4，`fixed` 是仅用于实验的 q8 构建。实验修改 GPU pipeline 的 dtype 与 WASM 首选 dtype 为 q8，没有将此配置纳入生产代码。

此机器的 q8 WebGPU Tiny 输出多种语言混杂的乱码，显式中文耗时 7.49–11.33 秒；q8 WebGPU Base 前两个样本也有乱码，约 12.9 秒。第三个 Base 样本触发现有超时/CPU 回退，WASM/q8 恢复合理中文输出，后续样本约 3.87–6.29 秒。结论只适用于这个模型导出、当前运行库与硬件组合：不能直接将 q8 设为 GPU 默认，也不能因此判断所有 q8 模型都不可用。

## 浏览器与代码验证

生产扩展的 X DOM 夹具已在基线复现 poster 延迟补全清空字幕，在候选版本验证保留时间轴和真正换媒体清理。该夹具使用已保存的字幕及固定翻译响应，不替换上述真实识别基准。源语言确认、CJK 预算、重复文本重试与缓存拒绝、同媒体身份以及 HLS 替代清单均有针对性回归。

最新主分支上的 18 个相关测试文件共 1,159 条通过，另 4 个字幕测试文件共 60 条通过；四个改动纯模块的语句、分支、函数、行覆盖率均为 100%。类型检查、Chrome/Firefox 生产构建、文档构建与测试清单审计通过。生产浏览器夹具 8 项通过，鼠标与节点变化没有重复缓存请求或 ASR。

`verificationOwnership.test.ts` 有一个既有失败：19 个其他模块未进入仓库要求的严格覆盖边界。在干净的 `a958891b3246da0335c0b4c3234755d286e8bd73` 快照与本任务上均复现相同列表；涉及 learningFeatures、popup mount、share-card、vocabulary、WebDAV properties 等，未放宽门禁或改动这些模块。本次验证是针对性回归，没有运行全量套件。

用户提供的两个真实 X 帖子在网页读取中分别返回 403 与读取失败，未取得原始音轨；Home 登录信息流也未做真实网络验收。合成普通话样本不能代表影视配乐、方言或真实帖子的识别准确率。部分 HLS 格式仍可能无法解码。

## 开源方案对照与下一轮准入

- 本地 `read-frog` 的 `request-ai-subtitles.ts` 使用服务端字幕任务及轮询，复用服务器任务状态和检测语言；它没有提供能直接替换当前浏览器 Whisper 的模型。`kiss-translator` 本次限定范围的字幕实现主要处理已有字幕翻译与对齐。借鉴了身份、任务复用的思路，生产代码按 FluentRead 架构独立实现，未复制参考仓库代码。
- [OpenAI Whisper](https://github.com/openai/whisper) 的官方转写实现有重复输出质量检查与受控重试；本次使用当前 Transformers.js 支持的生成参数重新实现，未照搬 Python 参数。
- [faster-whisper 的转写实现](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py)包含语言检测阈值与多片段检测。本次据此考察语言确认策略，保留显式语言优先和有界缓存。
- [live-subtitle](https://github.com/xu-0306/live-subtitle)把标签页音频流传给本机 WhisperLiveKit 服务。它能将重模型计算移出浏览器，但需要额外本机服务；本次没有添加此运行依赖。
- [SenseVoiceSmall](https://github.com/QwenAudio/SenseVoice)支持普通话、粤语、英文、日文和韩文，采用非自回归架构。[sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)提供 SenseVoice/VAD 的浏览器 WASM 示例。它是下一轮中文模型候选；项目公布的速度不能当作 FluentRead 浏览器里的实测速度，本次尚未接入或验证其准确率、内存和字幕时序。

下一轮替换模型应使用相同音频对照，增加真实普通话、粤语、英文、混语及配乐样本，分别报告原文 CER、句尾完整性、字幕边界、冷/暖耗时、CPU 时间和资源峰值。必须同时验证取消、缓存、下载状态、GPU 不可用时回退与跨视频隔离。按声称改进的场景确认收益后才改变默认模型，避免只提高模型大小或把失败转成看似成功的乱码。
