# 数据与隐私

FluentRead 浏览器扩展没有账号体系，也不会把使用记录、网页内容或 API 凭据发送到 FluentRead 自有服务器。翻译、词典和朗读功能仍可能调用你选择的第三方服务；是否出站取决于具体功能和服务配置。仓库中的独立 userscript 另有一项兼容规则请求，见下表。

## 哪些数据会离开浏览器

| 功能 | 可能发送的数据 | 接收方 |
| --- | --- | --- |
| 页面、划词和视频字幕翻译 | 待翻译文本、源语言、目标语言、模型和提示词；DeepL 等支持上下文的服务还会收到页面标题或调用上下文 | 当前选择的翻译服务或自定义端点 |
| 输入框翻译 | 输入框中的待翻译文本、源语言和目标语言 | Microsoft 翻译接口；此功能不跟随当前选择的翻译服务 |
| 免费翻译 | 待翻译文本 | 按 Microsoft、公共 DeepLX、Google 的顺序尝试，成功后停止回退 |
| AI 智能上下文 | 首次生成摘要时发送页面标题、描述和最多 4,000 字符的可读正文；翻译时发送该摘要、截断后的部分原始页面上下文和当前待翻译文本 | 当前 AI 翻译服务；此功能默认关闭 |
| 英文单词卡 | 被选中的单词会发送给公共词典服务；词典返回的释义和例句会发送给当前翻译服务生成译文 | 公共词典服务和当前翻译服务；不附带页面地址和正文上下文 |
| 划词朗读 | 需要朗读的文本与语言 | Microsoft Edge TTS；失败时可能回退到 Google TTS |
| 图片与圈选翻译 | OCR 识别出的文字 | 当前翻译服务 |
| 独立 userscript 的自动语言检测 | 待判断的文本片段 | 百度翻译语言检测接口；文本放在 POST 请求体中，不放入 URL |
| 独立 userscript 的站点兼容规则 | 当前页面的 origin（协议、主机名和端口），不含正文与查询参数 | FluentRead 的 `fr.unmeta.cn` `/preread`、`/read` 接口 |

图片 OCR 在扩展的 Offscreen 文档中本地执行。远程图片在需要识别时由扩展后台重新获取，请求不携带网页 Cookie；原图不会作为翻译请求直接发给所选文本翻译服务。圈选截图只在本次处理的内存中使用。

自定义接口、代理和本地服务由用户自行配置。使用非回环的 `http://` 地址时，文本和鉴权信息没有 TLS 传输保护；处理敏感内容时应使用可信的 `https://` 端点或本地回环地址，并核对服务方的数据保留政策。

FluentRead 在服务支持时优先使用请求头传递凭据，例如 Gemini 直连使用 `x-goog-api-key`。少数兼容接口把令牌定义为 URL 的一部分：DeepLX 的 Token 模板由用户明确选择；独立 userscript 的文心一言接口按服务协议把临时访问令牌放入查询参数。这类 URL 可能被网络诊断工具记录，使用时应避免共享完整请求地址。

## 浏览器内保存的数据

- 普通设置、配置历史、自动备份和 OCR 语言包状态统一保存在后台专属的 `FluentReadConfiguration` IndexedDB，不会写入当前网页的 `localStorage`。每条记录都使用 AES-GCM 和独立随机 IV 保存为密文；界面读取后仍展示明文。扩展声明 `unlimitedStorage` 以降低浏览器配额驱逐这份唯一配置副本的风险。
- 升级后的后台先检查加密迁移清理标记，再检查 IndexedDB 主配置；有标记时只恢复此前已经提交的完整快照和旧键清理，即使旧版本只有历史或凭据、没有主配置，也不会重新扫描残缺旧载体。无标记且主配置已经存在时直接使用，不再读取旧 storage。只有两者都不存在时才加载旧版配置；事务内会再次检查主记录或 marker，只允许一个完整旧快照写入并读回验证后再清理旧键。迁移数据与“待验证”加密清理标记会在同一个事务提交；该标记只为持久记录保存内容摘要，会话凭据只做 AES-GCM 认证，不留下可供离线猜测的摘要。读回成功后标记会先转成只含实际待删键的“已验证”状态，再开始删除旧载体，因此部分清理中断或后续配置变化都不会阻塞重试。若旧快照没有主配置，marker 会继续充当权威哨兵，直到默认主配置建立，避免并发慢迁移获得空窗。恢复过程不会读取或回灌旧值。
- API Key、Secret 等凭据统一以密文进入该 IndexedDB，并在浏览器或扩展重启后自动恢复。升级时若检测到上一版的 `session:credentials`，会先将其写入并读回验证持久凭据记录，再删除旧会话记录；中断时至少保留一份可恢复副本。
- 配置加密使用内置的 `FluentReadEncryption` 派生密钥，主要避免在 IndexedDB 和开发者工具中直接出现明文。能够读取扩展源码或控制本机浏览器资料的人仍可能恢复数据，因此它不能替代操作系统账号隔离，也不适合把共享或受控设备当作可信保险箱。
- 单词、掌握度和复习日志保存在独立的 `FluentReadVocabularyBook` IndexedDB。阅读上下文和去参数后的来源地址只在主动收藏时保存；导出默认不包含这些字段，只有用户明确勾选后才写入备份。
- 模型请求、Token、服务和模型统计保存在独立的 `FluentReadModelUsage` IndexedDB。事件采用字段白名单，不保存提示词、网页正文、网址或 API Key；模型用量导入按事件 ID 去重，冲突数据会被拒绝。
- “备份与恢复”会主动读取配置、单词本和模型用量，放入同一份带版本的 JSON。文件包含明文 API 凭据，导出时会询问是否额外包含阅读上下文，且文件本身不加密；单词本和模型用量不会进入每 6 小时的自动设置快照，翻译缓存也不进入备份。
- 配置历史不包含 FluentRead 专用凭据字段中的 API Key、Secret 或派生令牌，恢复历史也不会覆盖当前保存的这些凭据。自定义请求体、代理或端点会按普通设置保存和导出；如果你手动把 Bearer、查询令牌或用户信息嵌入其中，它们不会被自动识别或脱敏，请改用专用凭据输入框，并在分享导出内容前检查 JSON。
- 翻译缓存位于扩展后台的私有 IndexedDB；缓存键为不透明摘要。译文，以及启用 AI 智能上下文时生成的摘要和截断原始页面上下文，最多保留 24 小时，并受 2,000 条、5 MB 总量限制。可在弹窗中随时清空。
- 发布构建会移除 FluentRead 自有代码的控制台日志；开发源码也不应记录原文、译文、完整请求体、响应体或凭据。

旧版扩展曾把以 `flcache_` 开头的翻译缓存写入网页存储。当前版本加载页面时只清理这些旧 FluentRead 键和旧时间戳，不会清空网站自己的存储。独立 userscript 使用 userscript 管理器提供的 `GM_*` 私有存储；其中的原文与译文 HTML 缓存按每条记录的创建时间执行最长 24 小时硬过期，频繁访问不会续期，旧版无创建时间的缓存会在下次运行时删除。userscript 的服务令牌会跨浏览器重启保存在同一私有存储中。

## 用户可以怎样控制

1. 选择本地 Ollama 或浏览器内置翻译，减少文本出站。
2. 保持 AI 智能上下文关闭，避免发送额外的可读正文；普通翻译仍可能发送页面标题等调用上下文，详见上表。
3. 不要在共享或不受信任的设备上填写 API Key；离开设备前删除相关凭据或清除扩展数据。
4. 在弹窗中清空翻译缓存；在“备份与恢复”中迁移 FluentRead 数据，在“单词本 → 更多”中清空单词，并在“模型用量”页清除本机统计。
5. 撤销疑似泄露的 API Key，并在服务商控制台重新生成。
6. 提交 Issue 前删除 API Key、Cookie、个人信息和受保护的原文。

仓库还保留了[历史隐私政策归档](/guide/privacy-policy)，用于核对曾公开的政策文本；本页描述的是当前代码的数据流和用户控制。
